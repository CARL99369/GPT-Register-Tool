# Kakao Seed 派生兼容修复设计

## 目标

修复 Kakao 支付链路对固定同地区代理和 `sessid` 粘性会话格式的误判，同时保留跨地区派生时的代理链身份保护与出口国家预检。

## 根因

- 当前实现要求每条 Seed 都包含可改写的 `country/region`，因此固定 KR 代理即使实际出口为 KR，也会在预检前被拒绝。
- 即使 Seed 已经是目标国家，当前实现仍改写国家并给 Session ID 追加国家后缀。
- Session 正则只声明 `sid`，却会在 `sessid` 内部匹配 `sid`。
- 链路身份算法会无条件删除 Session ID 末尾两个大写字母，可能把供应商原始 Session ID 的自然后缀误认为程序追加的国家标签。

## 修复设计

- 仅修改 Kakao 提取器，不同步改变 iDEAL、TWINT 或 BLIK。
- 当 Checkout、Promotion、Provider 三个目标国家相同时：
  - 有国家选择器且已经匹配目标国家时，直接复用规范化后的原 Seed。
  - 没有国家选择器时，也直接复用同一固定代理；后续实际出口预检负责确认其国家。
- 当链路需要跨地区时：
  - Seed 必须包含可改写的 `country/region` 选择器，否则明确报错。
  - 只改写与目标不同的国家选择器。
  - 同时识别完整字段名 `sid` 和 `sessid`，为不同地区派生独立 Session ID。
- 链路身份校验使用派生上下文：只移除本次派生明确追加的国家标签，再与原 Seed 身份比较；不再猜测并删除原始 Session ID 的任意两个大写字母。
- 继续保留每个不同代理出口的国家预检、失败冷却和移除规则。

## 错误处理

- 同地区固定代理通过链路构建后，如果实际出口国家不符，仍由预检拒绝。
- 跨地区链路使用固定代理时返回清晰的“无法派生跨地区代理”错误。
- 不自动清除已有失败状态；默认冷却到期或新 Session ID 会自然恢复候选资格。

## 测试

- 固定、无国家选择器的代理可用于 `KR -> KR -> KR`，三个阶段得到完全相同的代理。
- `country=KR` 且包含 `sessid` 的 Seed 在全 KR 链路中保持不变。
- 原始 `sessid` 以两个大写字母结尾时不会发生身份误判。
- 跨地区派生可同时处理 `sid` 与 `sessid`，并保持原 Seed 身份一致。
- 无国家选择器的 Seed 在跨地区链路中仍被拒绝。
- 现有失败冷却、账号错误分类和 Checkout 形态测试继续通过。

## 完成标准

- 已报告的固定 KR 与 `sessid` 误判均有先失败后通过的回归测试。
- Kakao 单元测试及完整 Python 测试通过。
- SmsWorkbench Release 编译成功。

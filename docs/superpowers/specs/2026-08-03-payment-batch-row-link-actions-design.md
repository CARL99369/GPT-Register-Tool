# 批量协议支付结果行链接操作设计

## 目标

在“批量协议支付”窗口的每条结果行中提供“复制链接”和“浏览器打开”两个操作，让用户无需打开 JSON 报告即可使用已经生成的支付链接。

## 交互设计

- 在结果表格最右侧增加“操作”列。
- 每行显示“复制链接”和“浏览器打开”按钮。
- 按钮操作当前所在结果行，不依赖表格选中状态。
- 优先使用结果字段 `url`；当其为空时回退到 `long_url`。
- 仅接受绝对 HTTP 或 HTTPS 地址。缺少有效链接时，两个按钮保持禁用。
- 复制成功后，在窗口底部状态区显示简短确认。
- 浏览器启动失败时，在状态区显示明确错误，不改变批次结果或账号状态。

## 代码结构

- `PaymentBatchResultRow` 增加链接值和是否可操作的只读状态。
- `PaymentBatchViewModel` 在解析批次报告时保存链接，并暴露按行执行的复制与打开命令。
- 新增可注入的链接操作接口，封装剪贴板写入、HTTP(S) 校验和默认浏览器启动，避免 ViewModel 直接依赖 WPF 静态 API，便于自动化测试。
- `PaymentBatchWindow.xaml` 使用 `DataGridTemplateColumn`，通过行对象作为命令参数调用窗口 ViewModel 命令。

## 安全与边界

- 操作只处理已有链接，不重新发起提链或支付任务。
- 操作不写入 `paypal_status`、订阅类型或其他账号状态。
- 非 HTTP(S) 地址不会复制或打开。
- 不在状态文本中显示完整链接，避免额外暴露 checkout 会话标识。

## 测试

- 报告中的 `url` 会写入结果行。
- `url` 为空时使用 `long_url`。
- 有效 HTTP(S) 链接可复制、可打开。
- 空值及非 HTTP(S) 链接不会调用外部操作。
- 现有批次请求、报告打开和结果展示测试继续通过。

## 完成标准

- 每条带有效链接的结果行都显示两个可用按钮。
- 点击“复制链接”后，剪贴板获得该行链接。
- 点击“浏览器打开”后，系统默认浏览器打开该行链接。
- 无有效链接的结果行按钮禁用。
- 自动化测试与桌面端 Release 编译通过。

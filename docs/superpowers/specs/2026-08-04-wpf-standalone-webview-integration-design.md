# WPF 直绑支付 WebView2 集成设计

## 目标

将仓库根目录现有的 `5601` 直绑独立服务接入 SmsWorkbench。用户点击左侧“直绑支付”后，桌面端自动确认服务可用并在主窗口内嵌展示 `http://127.0.0.1:5601/`，不再要求手工运行脚本或切换到外部浏览器。

## 范围

- 在“支付管理”分组新增“直绑支付”导航按钮。
- 在现有账号工作区之外增加一个内嵌直绑工作区。
- 桌面端负责服务健康检查、后台启动、等待就绪、失败提示与重试。
- 内嵌工作区提供返回账号、重新加载和外部浏览器打开三个操作。
- 保留现有 `server.py`、`standalone_flow.py`、`standalone_core/` 和静态页面，不重写直绑业务逻辑。

不在本次范围内：把独立服务的数据迁入 SmsWorkbench SQLite、重写静态页面为原生 WPF 控件、修改直绑支付协议。

## 架构

### `IStandaloneServiceController`

向 UI 暴露固定服务地址和 `EnsureReadyAsync`。实现类依赖应用根目录，先请求 `/health`；服务未运行时，以隐藏后台进程启动根目录的 `run_direct.vbs`，随后在有界时间内轮询健康接口。

控制器采用单飞任务：连续点击或重复导航共享同一次启动过程，避免同时创建多个服务进程。已存在的外部 `5601` 服务只复用，不接管或终止。

### WPF 工作区

主内容区分为两个互斥视图：

- `AccountWorkspace`：现有概览、账号表格、任务与日志，启动时默认显示。
- `StandaloneWorkspace`：顶部紧凑工具栏和 WebView2 内容区。

点击“直绑支付”立即切换到直绑工作区并显示加载状态。服务就绪后初始化 WebView2 并导航到固定本机地址。点击“返回账号”只切换可见性，不停止服务；再次进入时复用已加载页面。

## 交互状态

- `Idle`：尚未打开直绑页面。
- `Starting`：健康检查或后台启动中，显示进度，禁用重复重试。
- `Ready`：WebView2 已导航，显示刷新和外部打开操作。
- `Failed`：显示简短错误与重试按钮，错误同时写入现有日志。

WebView2 导航失败进入 `Failed`，不影响账号工作区或其他后台任务。缺少 `run_direct.vbs`、WebView2 Runtime 或服务启动超时均提供明确错误，不静默失败。

## 依赖与发布

- 使用 `Microsoft.Web.WebView2` NuGet 包，并在 `Directory.Packages.props` 集中锁定版本。
- WebView2 用户数据放在仓库 `runtime/webview2/`，该目录已被 Git 忽略。
- 规范发布脚本继续输出到 `dist/net10`；NuGet 的 WebView2 Loader 和托管程序集随发布产物复制。
- 运行时仍以仓库根目录为服务工作目录，现有 `ApplicationPaths` 负责从 `dist/net10` 定位根目录。

## 生命周期

桌面端通过 `run_direct.vbs` 启动独立后台服务，不持有其进程句柄。关闭 SmsWorkbench 不强制终止一个可能由其他入口启动的 `5601` 服务，避免误杀共享进程。用户需要重启服务时仍可使用仓库现有 `restart_standalone.cmd`。

## 测试

- 控制器单元测试覆盖：健康服务不重复启动、未运行时仅启动一次、等待后就绪、超时和入口文件缺失。
- WPF 冒烟测试覆盖：左侧存在“直绑支付”按钮、两个工作区默认可见性正确、点击返回能恢复账号工作区。
- 运行完整 .NET 测试和 Python 测试，确认桌面集成未改变独立服务协议。
- 使用规范 `SmsWorkbench/build_dotnet.ps1` 发布桌面端，并确认 `dist/net10/SmsWorkbench.exe` 与 WebView2 依赖生成。

## 验收标准

1. 用户只需点击左侧“直绑支付”即可在主窗口内看到页面。
2. 服务未运行时桌面端会自动后台启动，重复点击不会启动多个实例。
3. 启动或导航失败时界面可重试，其他桌面功能仍可使用。
4. 用户可以返回账号列表、重新加载内嵌页面或用默认浏览器打开。
5. 桌面和 Python 全量测试通过，规范发布成功。
